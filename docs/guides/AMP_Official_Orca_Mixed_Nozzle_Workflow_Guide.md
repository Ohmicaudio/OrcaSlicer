# AMP Official Orca Mixed-Nozzle Workflow Guide

## Purpose

Use AMP's offline plan as a guide for the official Orca GUI mixed-nozzle setup.

This guide is for manual review and representation testing. It does not validate physical printing and does not replace Orca's official workflow.

## Required State

- Official Orca GUI.
- Repaired four-region probe models or equivalent user model split into meaningful region bodies.
- Mixed-nozzle toolchanger profile.
- No printing required.

## Tool Map

| AMP region intent | Orca tool slot | G-code command | Nozzle class |
| --- | ---: | --- | ---: |
| micro/detail | extruder 1 | `T0` | `0.2` |
| normal visible | extruder 2 | `T1` | `0.4` |
| structural shell | extruder 3 | `T2` | `0.6` |
| bulk | extruder 4 | `T3` | `0.8` |

## Manual Orca Steps

1. Create or select a toolchanger printer profile in official Orca.
2. Set the active tool nozzle diameters to `0.2`, `0.4`, `0.6`, and `0.8`.
3. Use percentage-based line widths where the official mixed-nozzle workflow requires nozzle-scaled widths.
4. Import the region bodies as separate objects.
5. Assign each object to the matching tool slot:
   - `micro_detail_zone.stl` -> extruder 1 / `T0` / `0.2`
   - `normal_visible_detail_zone.stl` -> extruder 2 / `T1` / `0.4`
   - `structural_shell_zone.stl` -> extruder 3 / `T2` / `0.6`
   - `bulk_zone.stl` -> extruder 4 / `T3` / `0.8`
6. Save the project as 3MF.
7. Reopen the 3MF and confirm object-to-tool assignments remain intact.
8. Export G-code.
9. Run the AMP validator against the exported G-code.

## Validator Command

Use the AMP packet and expected tool map generated by the workflow bridge:

```text
python tools/amp_validate_orca_mixed_nozzle_gcode_against_plan.py --packet outputs/amp_plan_packet_001 --gcode path\to\exported.gcode --expected-tool-map outputs/amp_orca_gui_workflow_bridge/expected_tool_map.json --out outputs/amp_orca_gui_workflow_bridge/orca_gui_gcode_validation.json --markdown outputs/amp_orca_gui_workflow_bridge/orca_gui_gcode_validation.md
```

## Expected Evidence

The exported G-code should show:

- a nozzle header containing the used classes `0.2`, `0.4`, `0.6`, and `0.8`
- active tools `T0`, `T1`, `T2`, and `T3`
- object comments or other region identity evidence for the four region bodies

An extra unused tool slot in the nozzle header is a warning, not a failure, if no extra active tool appears in the G-code.

## What AMP Validates

The validator checks the exported G-code against the AMP packet for representation conformance:

- expected nozzle classes
- expected active tools
- expected region names
- unexpected extra active tools
- forbidden claim text in generated artifacts

This is not a physical print validator.

## Non-Claims

- This guide does not validate physical printing.
- This guide does not prove U1 touchscreen compatibility.
- This guide does not bypass Snapmaker validation.
- This guide does not replace Orca's official workflow.
- This guide does not make AMP a production mixed-nozzle slicer.
- This guide does not prove independent per-tool layer height.
