# AMP Orca 3MF Handoff Parity 001

## Purpose

Compare the G-code produced from the automatic AMP-to-Orca 3MF handoff with the earlier manually configured official Orca mixed-nozzle baseline.

This comparison asks whether automation preserved the same region/tool/nozzle slicing behavior. It does not require byte-identical G-code and does not validate physical printing.

## Inputs

Manual official Orca baseline:

```text
C:\Users\d\Desktop\AMP Official Orca Mixed Nozzle GUI Probe\02_save_outputs_here\gcode\official_orca_mixed_probe_0p12_fixed_models.gcode
```

Automatic AMP handoff output:

```text
B:\ohmic\Snapmaker-OrcaSlicer\outputs\amp_orca_3mf_handoff\amp_generated_orca_handoff.gcode
```

Both were generated by official OrcaSlicer v2.4.1 from the same four-object mixed-nozzle project geometry and profile state.

## Conformance Result

Both files pass the AMP G-code conformance validator for:

- planned nozzle classes `0.2`, `0.4`, `0.6`, and `0.8`;
- active tool commands `T0`, `T1`, `T2`, and `T3`;
- all four region identities;
- no additional active tool beyond the unused fifth preset slot;
- no forbidden safety or touchscreen claims.

Automatic handoff validator result:

```text
PASS
errors=0
warnings=3
```

The warnings cover the unused fifth tool slot, the shared/global layer-height limitation, and the shared mixed-probe process ID.

## Raw Difference Review

The raw files are not byte-identical:

```text
manual SHA-256: BE98F6BE1A473425B0A37EF505F517119725DF9638D055FB823C50E6E17083A1
automatic SHA-256: 730BE59D77C0A6D089A46829235E0A5BFB74C8F6793C700C1302BF6D99D65D9A
```

The diff contains 95 inserted and 96 removed lines across approximately 44,000 lines. Reviewed differences consist of:

- the Orca generation timestamp;
- M73 progress commands moving by one or several adjacent moves;
- equivalent small-loop traversal ordering in the micro-detail region;
- one fewer raw line in the automatic output.

The aggregate extrusion, travel, layer, tool, role, and time metrics remain identical. Therefore this result is normalized behavioral parity, not byte parity.

## Decision

The automatic AMP 3MF handoff preserves the manual official Orca baseline's measured slicing behavior for this four-region probe.

The handoff has removed manual object-to-tool assignment without changing the observed tool ladder, tool command count, path counts, extrusion total, role counts, layer count, or slicer-derived time estimate.

Future regression checks should compare normalized metrics and AMP plan conformance rather than requiring byte-identical G-code. Raw byte identity is too sensitive to timestamps, progress-command placement, and equivalent traversal ordering.

## Non-Claims

- This does not prove physical U1 mixed-nozzle behavior.
- This does not prove print strength, bonding, surface quality, or dimensional accuracy.
- This does not prove touchscreen compatibility.
- This does not bypass Snapmaker validation.
- Hardware preflight remains `not_ready`.
