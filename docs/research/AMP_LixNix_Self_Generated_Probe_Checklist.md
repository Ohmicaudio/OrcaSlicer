# AMP LixNix Self-Generated Probe Checklist

## Purpose

This checklist defines the probe geometry and G-code inspection expectations AMP will use when a LixNix `multi_nozzle_multi_layer_height` executable becomes available.

AMP will generate its own probe models. The collaboration request to LixNix should focus on build/runtime workflow and expected output behavior, not on asking the author to supply geometry.

## Probe Models

Generated by:

`tools/amp_generate_lixnix_probe_models.py`

Ignored output directory:

`outputs/lixnix_runtime_probe/models/`

Models:

- `lixnix_two_object_detail_bulk.stl`
- `lixnix_four_region_tool_ladder.stl`
- `lixnix_support_restriction_probe.stl`
- `lixnix_layer_height_probe.stl`

## Model Intent

### Two-Object Detail/Bulk

Purpose:

- Check manual assignment across separate objects.
- Put fine/detail geometry and coarse/bulk geometry on the same plate.

Expected use:

- Assign detail object to a fine or normal tool.
- Assign bulk object to a coarse tool.

### Four-Region Tool Ladder

Purpose:

- Provide four visually separated regions for manual 0.2 / 0.4 / 0.6 / 0.8 style assignment.

Expected use:

- Fine/detail region: small nozzle / fine layer.
- Normal visible region: normal nozzle / normal layer.
- Structural shell region: structural nozzle / thicker layer if supported.
- Bulk region: bulk nozzle / coarse layer if supported.

### Support Restriction Probe

Purpose:

- Expose support, raft, or interface behavior.
- Probe whether `support_nozzle_diameter` affects support assignment.

Expected use:

- Compare output with unrestricted support and nozzle-restricted support.

### Layer-Height Probe

Purpose:

- Expose per-extruder layer-height behavior.
- Include both tall simple vertical geometry and stepped/tapered geometry that may force fallback.

Expected use:

- Assign one region/tool to a coarse preferred layer height.
- Inspect whether coarse layers appear only where geometry permits.

## G-code Inspection Tool

Use:

```powershell
python tools/amp_inspect_mixed_nozzle_gcode.py outputs/lixnix_runtime_probe/gcode --out outputs/lixnix_runtime_probe/reports
```

The tool reports:

- `nozzle_diameter` header values.
- `print_settings_id`.
- T command counts.
- Active tools observed.
- Layer heights observed.
- Per-tool extrusion counts.
- Wipe tower comment hits.
- Purge/flush comment hits.
- Support/raft/interface comment hits.
- Line-width comment hits.
- Possible mixed-nozzle evidence.
- Warnings when only one tool or one nozzle value appears.

## Expected Inspection Points

When LixNix runtime output is available, inspect:

- Multiple `nozzle_diameter` values in comments or metadata.
- Distinct tool commands such as `T0`, `T1`, `T2`, or `T3`.
- Different active tools associated with different regions or objects.
- Per-extruder layer heights visible in Z-step patterns.
- Wipe tower or purge behavior when tool changes occur.
- Support nozzle restrictions, especially for support/raft/interface paths.
- Whether 3MF/project save/load preserves mixed settings.
- Whether behavior is manual/per-extruder rather than automated geometry-driven planning.

## AMP Interpretation Rules

- Multiple tools plus multiple nozzle metadata would be runtime evidence of mixed-nozzle plumbing.
- Per-extruder layer-height output would be runtime evidence that the LixNix layer-combination path is active.
- A single tool and single nozzle value means the probe did not exercise mixed-nozzle behavior.
- G-code output alone does not validate physical print behavior.
- LixNix runtime output does not mean AMP implements mixed-nozzle slicing.
- Snapmaker U1 touchscreen compatibility remains unproven unless specifically tested on U1 paths.

## Questions For LixNix Author

Use the self-generated probes as the baseline and ask about workflow, not geometry:

- Which branch/commit should be used for runtime tests?
- What Windows dependency setup is expected?
- Is the intended workflow GUI, 3MF/project, config profiles, or fff_print tests?
- Should output G-code contain multiple nozzle diameter values?
- Should per-extruder layer heights appear in final G-code Z steps?
- Does 3MF save/load preserve the mixed nozzle and layer-height settings?
- Are there expected-output G-code fixtures for comparison?
